# k6

**Definition:** A developer-friendly load testing tool where tests are written as JavaScript scripts, used to simulate many concurrent users hitting an API or website.

## Core Services & Concepts
- **Virtual Users (VUs)** — simulated concurrent users, ramped up gradually to find where a system breaks
- **Thresholds** — pass/fail criteria (e.g. "95% of requests must complete under 200ms") that can fail a CI pipeline automatically
- **Scripted scenarios** — [[Rate Limiting Algorithms]], tests can simulate realistic traffic patterns, not just flat request floods

## Pros
- Tests are real code (JavaScript), version-controllable alongside the application
- Lightweight and fast compared to older Java-based load testing tools like JMeter
- Integrates cleanly into CI/CD pipelines with pass/fail thresholds

## Cons
- Smaller ecosystem and plugin library than long-established tools like JMeter
- Requires some scripting comfort, less point-and-click than GUI-based load testers

## Best For
- Developers wanting load testing that lives in code and CI, not a separate GUI tool

## Real Examples
- Used by engineering teams to load-test APIs before major launches or traffic events

## Use Cases
- Load and stress testing APIs before launch
- Capacity planning, finding the point where response times degrade
- Regression-testing performance as part of CI/CD
